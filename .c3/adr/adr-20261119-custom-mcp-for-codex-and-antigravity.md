## Goal

Give Codex and Antigravity sessions, in main chats and in subagent runs alike, every enabled custom MCP server from Settings → MCP servers (`customMcpServers`), the same set a Claude session gets: enabled entries only, never the reserved name `kanna`, with a fresh OAuth bearer in the headers. Kanna's own agent-tools bridge grant stays main-only and unchanged.

## Context

Only the Claude path consumed `customMcpServers` (`claude-subagent-wiring.ts`, `claude-session-spawner.ts`, `claude-session-start.ts`). `CodexAppServerManager.startSession` sent a thread `config` of only `tools.update_plan`, and `AntigravityAcpManager.openSession` sent `mcpServers` holding only the main-scope bridge grant, so a sub scope got `[]`. A subagent switched from Claude to Codex or Antigravity silently lost every `mcp__<name>__*` tool and nothing in the UI said so (reported from Aegis, TaoRory/aegis-mkt#84). c3-211 recorded that `ThreadStartParams` carries no `mcpServers`, which is literally true but missed that `ThreadStartParams.config` is a free-form override map (`additionalProperties: true` in the schema generated by `codex app-server generate-json-schema`). A live probe against codex-cli 0.157.0 showed `config["mcp_servers.<name>"]` with a stdio entry and with `{ url, http_headers }` both connect and list tools via `mcpServerStatus/list`; a probe against agy 1.5.9 showed ACP `session/new` `mcpServers` accepts `{ type: "http", name, url, headers: [{name, value}] }` and `{ name, command, args, env: [{name, value}] }`, with headers and env reaching the server. Codex and agy run with approvals off (`approvalPolicy: "never"`, `--dangerously-skip-permissions`) and without the project's `.claude/settings.json` hooks.

## Decision

`createCustomMcpServerResolver` in `claude-session-config-helpers.ts` (c3-210) is the one owner of "which servers, with which bearer": it composes `getEnabledCustomMcpServers` (now also excluding `kanna`) and `buildOAuthBearers`, merges each bearer into the server's `headers`, and returns `{ servers, usableUntil }`. `server.ts` builds it once and `createPeerMessaging` (c3-249) injects it into both managers as the `resolveCustomMcpServers` port, so no caller (claude-turn-starter, subagent-provider-run) changes. Each manager maps the grant to its own wire shape on every session open: Codex adds per-name dotted keys `mcp_servers.<name>` to the thread `config` of `thread/start`, `thread/resume` and `thread/fork` (per-name keys merge with the user's own `~/.codex` servers, where a nested `mcp_servers` object would replace them); Antigravity lists the servers in `session/new` and `session/resume` `mcpServers`, ahead of the main-only bridge grant. Only `stdio` and `http` are mapped; `sse` and `ws` entries are skipped with a `log.warn` naming them. Each manager stores the grant's `usableUntil` and respawns a reused session on the next `startSession` once it passes, unless a turn is running, mirroring the Claude stale-bearer respawn. The user chose all enabled servers over a per-subagent allowlist, accepting that these providers run the tools without an approval step.

## Alternatives Considered

| Alternative | Rejected because |
| --- | --- |
| Per-subagent opt-in server list, default none | The user chose parity with Claude; a list that Claude ignores would itself be a silent no-op, and it adds a settings field copied by hand across app-settings normalize, create and update |
| Write servers into ~/.codex/config.toml or agy's own config | User-global, outlives the run, leaks to every session, and mutates files Kanna does not own |
| Pass Codex servers as one nested mcp\_servers object | A nested table override replaces the user's own Codex MCP servers instead of merging with them |
| Fail the session when an sse or ws server is enabled | One unsupported server would break every Codex and Antigravity chat; the server still reaches Claude, and the skip is logged and documented |
