Kanna supports four providers — Claude, Codex (OpenAI), Antigravity (Google),
and OpenRouter — switchable per-chat from the composer.

## Provider switcher

The composer's provider button picks between Claude, Codex, Antigravity, and
OpenRouter. Each provider exposes its own model list and reasoning controls.

## Claude

Register one or more Claude OAuth tokens in **Settings → Providers → "Claude
OAuth tokens"**. Kanna rotates across them per chat and falls over automatically
when one hits a rate limit — see [OAuth Pool Setup](/getting-started/oauth-pool-setup/).

| Model | Reasoning efforts | Context window |
| --- | --- | --- |
| Fable 5 | low / medium / high / xhigh / max | 200k or 1M |
| Opus 5 | low / medium / high / xhigh / max | 200k or 1M |
| Sonnet 5 | low / medium / high / xhigh / max | 200k or 1M |
| Opus 4.8 | low / medium / high / xhigh / max | 200k or 1M |
| Opus 4.7 | low / medium / high / xhigh / max | 200k or 1M |
| Sonnet 4.6 *(default)* | low / medium / high / max | 200k or 1M |
| Haiku 4.5 | low / medium / high | 200k |

**The 1M context window is a per-chat toggle, not a separate model.** Pick the
model, then pick its window; Kanna appends the `[1m]` suffix the API expects
when you choose 1M. A model that offers only 200k shows no toggle.

If a chat is quietly compacting far below the window you expected, the window
probably fell back to 200k — Kanna logs a warning whenever the requested window
is not the one it resolved.

### Code Mode and permissions

**Code Mode (experimental)** lets Claude write one script that batches many tool
calls instead of issuing them one at a time. It is on by default and has an
**Off / On** switch in **Settings → Providers → "Code Mode (experimental)"**. The
switch applies to new Claude sessions, subagent runs included. A session keeps
the mode it started in, and toggling the switch never restarts a live session.
Claude Code decides eligibility itself: an older model, or a custom endpoint,
starts the session without Code Mode. Each call a script makes still appears in
the transcript as an ordinary tool call, and loop and Inbox guards still apply to
it.

A session that started in Code Mode cannot be resumed without it, for example
after you turn the switch off or pick a model that Code Mode does not support.
Kanna detects that refusal and reruns the turn on a fresh session primed with the
chat history, the same recovery it uses when a Claude session file has been
deleted.

Claude chats run in `bypassPermissions` ("yolo") mode, so tool calls run without
an approval prompt. Plan mode still plans first, and `AskUserQuestion` still asks.
When Kanna runs as root and the environment is not marked as a sandbox
(`IS_SANDBOX=1` or `CLAUDE_CODE_BUBBLEWRAP`), Claude Code refuses that mode, so
Kanna falls back to `acceptEdits`.

## Codex

- **Auth** — handled entirely by the `codex` CLI. Kanna spawns
  `codex app-server` with its own environment inherited, and injects no
  credentials of its own. If `codex` works in your shell it works in Kanna,
  whether that is a `codex login` session or an `OPENAI_API_KEY` you export
  before starting Kanna.
- **Models** — GPT-5.5 *(default)*, GPT-5.4, GPT-5.3 Codex, GPT-5.3 Codex Spark.
- **No reasoning-effort selector.** Codex models carry no effort options in
  Kanna's catalog; the picker shows models only.

- **Plan progress** — Kanna turns on Codex's `update_plan` tool and tells the model
  to publish its plan through it. Each time Codex updates the plan, the steps and
  their status (pending, in progress, completed) show up in the chat as a task
  list, the same way Claude's task list does, so you can follow a long Codex turn.

Codex also has no compaction request of its own, so `/compact` on a Codex chat
is [summarised by Kanna itself](/features/slash-commands/#compact).

## Antigravity

Antigravity runs Google's `agy` CLI. Kanna talks to it over the Agent Client
Protocol on stdio, so one `agy` process serves a chat the way one `codex
app-server` process serves a Codex chat.

- **Prerequisites** — `agy` v1.5.9 or newer on the `PATH` of the shell that
  starts Kanna, and logged in. Run `agy` once and sign in, or run
  `agy acp --login`. Kanna injects no credentials of its own; if `agy` works in
  your shell it works in Kanna.
- **Models** — Gemini 4 Carbon *(default)*, Gemini 4 Argon, Gemini 4 Hydrogen,
  Gemini 3.8 Flash, Claude Opus 5.5, Claude Sonnet 5.5.
- **Reasoning effort** — low / medium *(default)* / high, set per chat. There is
  no fast mode and no context-window picker.
- **Plan mode** — the composer's plan toggle puts `agy` in its plan mode. When it
  finishes planning, Kanna shows the plan document as a plan to approve, the same
  way it does for Claude.
- **Approvals** — `agy` is started with `--dangerously-skip-permissions`, so tool
  calls run without a permission card. This matches Codex running with its
  approval policy set to never; the agent can edit files and run commands in the
  chat's directory without asking.
- **Resume** — a chat keeps its `agy` session and resumes it after the process
  or Kanna restarts. If `agy` no longer has that session, Kanna starts a new one
  with the same instructions, and the model does not remember the earlier turns.
- **`/compact`** — passed straight to `agy`, which compacts natively, so Kanna
  does not summarise it itself. See [`/compact`](/features/slash-commands/#compact).
- **Messaging between chats** — Kanna gives the agent `list_peer_chats`,
  `send_chat_message` and `wait_for_chat_message`, served to `agy` as a local MCP
  server. See [Messaging between chats](/guides/user/peer-messaging/#antigravity-chats).
- **Subagents** — an [Antigravity subagent](/guides/user/subagents/) runs in its
  own `agy` session. It does not get the messaging tools.

Limits to know about:

- **No fork.** Forking an Antigravity chat starts a new `agy` session; it does not
  continue the original one.
- **No steering.** A message sent mid-turn waits in the queue and runs when the
  turn ends; it cannot redirect the running turn.
- **No custom models.** Settings → Models cannot add Antigravity models.
- **Questions arrive as plain text.** When `agy` asks you something, the question
  shows as ordinary reply text, not as a question card.
- **Some tools look generic.** `list_dir`, `grep_search` and `find_by_name` render
  as generic tool entries rather than dedicated ones.

## OpenRouter

- **API key auth** — set the LLM provider to OpenRouter and paste an OpenRouter
  API key in **Settings**. Turns run against OpenRouter's Anthropic-compatible
  endpoint (the key is injected as `ANTHROPIC_AUTH_TOKEN`; any
  `ANTHROPIC_API_KEY` is cleared).
- **Live model catalog** — the OpenRouter model picker populates dynamically
  from OpenRouter's public `/api/v1/models` endpoint, filtered to tool-capable
  models and cached for ~1 hour.
- **Billed by OpenRouter** per token, independently of your Claude plan.

## Switching mid-chat

Provider and model can change mid-chat. The new turn uses the picked provider;
previous turns stay exactly as they are.

## Editing the model catalog

**Settings → Models** is full CRUD over the Claude and Codex model lists, so a
model that ships before Kanna knows about it is one form away from usable.

- Every built-in appears as an **editable copy**, so you can adjust a label or
  the offered efforts without waiting for a release.
- Adding an entry whose id matches a built-in **merges** over it field by field
  — fields you did not set keep their built-in values.
- Adding a new id **appends** it to that provider's list.
- Deleting an edited built-in **reverts to the built-in**. Deleting a purely
  custom id removes it.

Built-ins are never destroyed, so the catalog cannot end up empty.

:::note
Providers themselves are fixed — you can add models, not a fifth provider.
Antigravity and OpenRouter are not editable here: Antigravity's models are fixed,
and OpenRouter's catalog is already fetched live.
:::
